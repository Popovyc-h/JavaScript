## Завдання 1. Багатоканальний шлюз сповіщень: Promise API комбінатори та симуляція життєвого циклу повідомлень (Event Loop Queues, Multi-provider Fallback, ES Modules)

У реальних проєктах (інтернет-магазини, банкінг, служби доставки) критично важливі події (підтвердження оплати, OTP-коди, статус замовлення) розсилаються через кілька каналів: SMS, Telegram-бот, Push-сповіщення та Email. Провайдери зв'язку мають різний час відгуку, ліміти та стабільність. Система повинна оперативно доставляти сповіщення через найшвидший або резервний канал, вести повну зведену статистику відправки, контролювати таймаути та правильно координувати черги браузера (Call Stack, мікротаски та макротаски).

**Що потрібно зробити:**

1. Створити модуль емуляції відправки сповіщень через провайдери та утиліту гарантованого таймауту (`sender.js`):
    - Реалізувати функцію `dispatchNotification(channel, payload)`:
        - Повертає `Promise`.
        - Через `setTimeout` тривалістю `channel.latency` мс:
            - Якщо `channel.fail === true` — відхиляє проміс із помилкою `new Error(`[${channel.type}] ${channel.error || 'Збій каналу'}`)`.
            - Якщо `channel.fail === false` — успішно резолвить об'єкт квитанції:
              `{ channel: channel.type, provider: channel.name, deliveredAt: new Date().toISOString(), cost: channel.cost }`.
    - Реалізувати функцію `withDeadline(promise, timeoutMs, deadlineMsg)`:
        - За допомогою комбінатора `Promise.race` конкурує між цільовим `promise` та штучним промісом-таймаутом, який реджектиться через `timeoutMs` мс.
    - Експортувати створені функції за стандартом ES Modules (іменований експорт).

```javascript
// Приклад швидкої перевірки таймауту відправки
const slowEmail = new Promise((res) => setTimeout(() => res('Email доставлено'), 300))

withDeadline(slowEmail, 150, 'Перевищено дедлайн відправки email')
    .then(console.log)
    .catch((err) => console.warn(err.message)) // "Перевищено дедлайн відправки email"
```

2. Реалізувати модуль оркестрації каналів (`orchestrator.js`) з використанням `Promise.any`, `Promise.allSettled` та `Promise.all`:
    - Імпортувати `dispatchNotification` та `withDeadline` із модуля `sender.js`.
    - Функція `sendUrgentOtp(channels, payload)` (Миттєва доставка першим доступним каналом):
        - Використовує `Promise.any` для запуску відправки по всіх каналах одночасно.
        - Повертає результат найшвидшого каналу, який виконав доставку без збою.
        - Якщо всі канали відмовили — перехоплює `AggregateError`, виводить перелік причин збою кожного провайдера та повертає статус `{ success: false, reason: 'Усі канали доставки недоступні' }`.
    - Функція `broadcastToAll(channels, payload)` (Широкомовна розсилка без втрати загального результату):
        - Використовує `Promise.allSettled`, щоб відправити сповіщення через усі зазначені канали й дочекатися завершення кожного (як успіхів, так і помилок).
        - Формує фінальний звіт:
            - `delivered`: масив назв каналів, які успішно доставили повідомлення.
            - `failed`: масив об'єктів помилок `{ channel, error }`.
            - `totalCost`: загальна сума витрат на доставлені повідомлення.
    - Функція `verifyAllRequiredChannels(channels, payload)` (Сувора системна валідація):
        - Використовує `Promise.all`, щоб переконатися, що обов'язкові службові сервіси відповіли одночасно.
        - Якщо бодай один канал відхилено — весь пакет вважається проваленим і переходить у блок `.catch()`.

```javascript
// Демонстрація широкомовного звіту через broadcastToAll
broadcastToAll(alertChannels, notificationPayload).then((report) => {
    console.log('Підсумок розсилки:', {
        успішно: report.delivered,
        помилки: report.failed,
        вартість: `${report.totalCost} грн`,
    })
})
```

3. Симуляція Event Loop браузера для чат-месенджера: мікротаски, таймери та Call Stack (`lifecycle.js`):
    - Створити функцію `simulateMessagePipeline(messageText)`:
        - Продемонструвати порядок виконання операцій під час відправки повідомлення користувачем у браузерному чаті:
            1. **Call Stack (Синхронно)**: Логування натискання кнопки "Надіслати" та синхронне додавання тексту в тимчасовий буфер вводу.
            2. **Microtask Queue (`Promise.resolve().then(...)`)**:
                - Мікротаска 1: Валідація тексту на цензуру / довжину до будь-яких відкладених завдань.
                - Мікротаска 2 (вкладена в першу): Оновлення локального бейджа "повідомлення в черзі відправки" (`queueMicrotask` або вкладений `.then()`).
            3. **Macrotask Queue (`setTimeout(..., 0)`)**:
                - Макротаска 1: Спрацьовування таймера Web API для мережевого пінгу або оновлення звуку відправки.
            4. **Call Stack (Синхронно)**: Завершення роботи синхронного обробника події кліку `"Обробник події кліку завершено"`.
    - Запустити функцію та додати пояснення у вигляді коментаря: чому саме черга мікротасок виконується раніше за макротаски, навіть якщо таймер мав затримку `0ms`.

```javascript
// Очікуваний вивід у консолі:
// [1 - Sync] Клік користувача: повідомлення передано в обробку
// [2 - Sync] Обробник події кліку завершено (Call Stack очищено)
// [3 - Microtask] Валідація тексту повідомлення успішна
// [4 - Microtask] Локальний статус оновлено: 'sending'
// [5 - Macrotask] Web API таймер: звук відправки повідомлення зіграно
```

2. Реалізувати алгоритми підбору відповідей у `botRouter.js` за допомогою Promise API:

## Додаткові вимоги

1. **Обов'язкова умова вибору:**
    - Для максимальної оцінки **12 балів** обов'язково виконати **лише 1 завдання із 2-х** (на ваш вибір).
    - Якщо виконано обидва завдання — викладач оцінює найкраще, а друге зараховується як додатковий плюс та практичний бонус.
2. **Робота з комбінаторами Promise API:**
    - Обов'язково застосовувати правильні методи відповідно до бізнес-задачі:
        - `Promise.all` — коли потрібні відповіді від усіх провайдерів або операцій без винятку (fail-fast поведінка).
        - `Promise.allSettled` — коли необхідно дочекатися кожного запиту (успішного чи збійного) без ризику переривання через один збій.
        - `Promise.race` — для реалізації таймаутів та змагання операцій на швидкість (перший fulfilled або rejected).
        - `Promise.any` — коли достатньо хоча б одного успішного результату (ігнорує помилки, поки є хоч один робочий варіант; падає лише з `AggregateError`, якщо всі провалилися).
3. **Модульна система ES Modules:**
    - Дотримуватися зазначеної файлової структури модулів.
    - Використовувати нативний синтаксис `import` та `export`.
    - Для локального запуску в Node.js додати `"type": "module"` у `package.json` або використовувати розширення `.mjs`.
4. **Розуміння та аналіз Event Loop:**
    - Чітко демонструвати знання порядку обробки завдань браузерним рушієм:
      `Синхронний Call Stack -> Вичерпання черги Microtasks (Promise, queueMicrotask) -> Фаза оновлення/рендерингу UI -> Наступна Macrotask (setTimeout, події таймерів)`.
5. **Чистота коду та оформлення:**
    - Дотримуватися зрозумілого та інформативного неймінгу змінних, констант і функцій.
    - Виводити в консоль наочні результати роботи кожного створеного методу.
